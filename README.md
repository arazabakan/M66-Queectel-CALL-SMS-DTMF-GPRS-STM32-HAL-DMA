‫# Quectel M66 Setup Guide with STM32F4 HAL and Keil MDK

This guide is written for the files `m66_f4.c` and `m66_f4.h`. Practical examples are available in `m66_examples.c`.

> **Validation Status:** This guide and the examples are not a substitute for testing on real hardware. AT commands and features such as HTTP, HTTPS, FTP, and MQTT depend on the modem's firmware version. Before final product deployment, test every feature with the AT manual of the exact firmware version.

## 1. Hardware Connection

Minimum connections:

STM32F4	Quectel M66	Description
UARTx_TX	Modem RXD	Follow the modem's allowed input voltage level; do not connect 5V directly.
UARTx_RX	Modem TXD	Common ground is mandatory.
GND	GND	Common ground and proper current return path
Power Supply	Modem VBAT	Power supply must handle GSM transmit burst current peaks.
Optional GPIO	PWRKEY	Follow the reference circuit and datasheet timing of the modem
Optional GPIO	STATUS/RESET	If used, follow the actual board circuit

**Power Warning:** The GSM modem draws high instantaneous current during transmit bursts. Use a proper lab power supply, place capacitors close to the modem, and ensure low-impedance power routing. Voltage drops can cause resets, UART disconnection, or network registration failure.

## 2. Project Creation in STM32CubeMX

### 2.1 Microcontroller Selection

1. In CubeMX, select the exact part number of your board (e.g., one of STM32F401/F407/F429/F446). The library relies on the `stm32f4xx_hal.h` family, but DMA resources, stream/channel numbers, and UART capabilities differ between models.
2. Configure Clock Configuration according to your crystal and actual board design.
3. Generate HAL code for the same STM32CubeF4 version. Do not mix HAL files from different versions.

### 2.2 UART Selection

1. Choose a free UART/USART (e.g., USART2).
2. Enable Asynchronous mode.
3. Map TX and RX to the pins actually connected to the modem.
4. Recommended starting settings: **115200 baud, 8 data bits, no parity, 1 stop bit, no hardware flow control**. If the modem is configured for a different baud rate, match the UART settings accordingly.
5. In the project, the selected handle (e.g., `huart2`) is referenced in `M66_Config`. You do not need to edit the library for a different UART.

### 2.3 DMA Configuration

For the selected UART, enable DMA for RX and TX in CubeMX if you want TX DMA as well. Directions should be:

- RX: Peripheral-to-Memory
- TX: Memory-to-Peripheral
- Peripheral increment: Disabled
- Memory increment: Enabled
- Data width: Byte for both Peripheral and Memory
- Reception Mode: The library switches to Circular in `M66_RX_CIRCULAR` mode at runtime.
- DMA Priority: Choose appropriate priority if the bus is busy. However, high priority alone does not prevent buffer overflow.

In NVIC, enable the DMA Stream interrupts for RX/TX. If UART Error IRQ is needed, also enable the USART interrupt. Check `stm32f4xx_it.c` to ensure the DMA handlers generated by CubeMX exist and call `HAL_DMA_IRQHandler()`. CubeMX usually handles this.

> In `M66_RX_CIRCULAR` mode, the library collects received bytes by reading the DMA counter in `M66_Process()`. Therefore, `M66_Process()` must be called regularly, and the application should not stay blocked in long functions or delays. Circular DMA cannot detect multiple full buffer wraps during long consumer stalls.

### 2.4 Code Generation

Generate code with your preferred tool (e.g., STM32CubeIDE or CubeMX with the appropriate Toolchain). Then open or import the project into Keil. CubeMX can usually generate a Keil project directly. In Project Manager, set Toolchain/IDE to MDK-ARM if you choose this path.

## 3. Keil MDK Project Setup

1. Add the following files to a group such as `M66 Driver`:
   - `Inc/m66_f4.h`
   - `Src/m66_f4.c`
   - `Examples/m66_examples.c` (if needed)
2. Add the `Inc` folder path in **Options for Target → C/C++ → Include Paths**.
3. The HAL files for the selected MCU and the startup/CMSIS files generated by CubeMX must be in the project.
4. In **Options for Target → C/C++**, select the C standard matching your project settings. The code uses common C features and HAL.
5. Ensure there is only one version of each HAL file and only one definition of HAL callbacks in the entire project.
6. `printf()` in the examples is not connected to debug output unless you retarget it yourself. You can replace it with SWO, RTT, or UART logging.

## 4. Library Configuration and UART Selection in Init

The example below selects UART2. To use another UART, simply change `huart2` to the corresponding handle (e.g., `huart1` or `huart3`). DMA numbers must also match CubeMX.


#include "m66_f4.h"
#include <string.h>

extern UART_HandleTypeDef huart2;
static M66_Handle hm66;

static void M66_AppInit(void)
{
    M66_Config cfg;
    memset(&cfg, 0, sizeof(cfg));

    cfg.huart = &huart2;
    cfg.hdma_rx = NULL; /* Uses huart2.hdmarx */
    cfg.hdma_tx = NULL; /* Uses huart2.hdmatx if configured */
    cfg.rx_mode = M66_RX_CIRCULAR;
    cfg.rx_dma_size = M66_RX_DMA_SIZE;
    cfg.tx_queue_size = M66_TX_QUEUE_SIZE;
    cfg.default_timeout_ms = 3000U;
    cfg.prompt_timeout_ms = 5000U;
    cfg.enable_rx_half_callback = 1U;

    if (M66_Init(&hm66, &cfg) != M66_OK)
    {
        /* Log the initialization error to log/LED */
        Error_Handler();
    }
}

M66_Init() must be called after MX_DMA_Init() and MX_USART2_UART_Init(). The MX_..._Init() function names depend on your CubeMX project.
5. Connecting HAL Callbacks

The library needs its internal handle. Therefore, the public HAL callbacks must forward it to the library wrapper functions. Place the following sample in your application file and adjust the UART name to match your choice:

extern UART_HandleTypeDef huart2;
static M66_Handle hm66;

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if (huart == &huart2)
    {
        M66_UART_RxEventCallback(&hm66, Size);
    }
}

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2)
    {
        M66_UART_TxCpltCallback(&hm66);
    }
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2)
    {
        M66_UART_ErrorCallback(&hm66);
    }
}

Important: Do not define these callbacks twice. If the project already has these functions, add the M66 condition inside the existing function. In Circular mode, reception is handled by polling the DMA counter in M66_Process(). The reception callback alone does not replace M66_Process().
6. Main Loop and Periodic Servicing

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_DMA_Init();
    MX_USART2_UART_Init();

    M66_AppInit();

    while (1)
    {
        M66_Process(&hm66);
        /* Keep other application tasks short and non-blocking */
    }
}

Do not call M66_Process() only once per loop iteration if the loop may stall for hundreds of milliseconds. In an RTOS, run it from a task with a short, fixed period. Avoid executing blocking AT commands inside reception callbacks or event callbacks.
7. Receiving Events

static void M66_OnEvent(const M66_Event *event, void *user)
{
    (void)user;
    if (event == NULL)
    {
        return;
    }

    switch (event->type)
    {
    case M66_EV_READY:
        /* Modem is reported ready to respond */
        break;
    case M66_EV_SMS_NOTIFICATION:
        /* New message notification; read SMS via API if needed */
        break;
    case M66_EV_SOCKET_DATA:
        /* Socket data reported; use read API for payload */
        break;
    case M66_EV_UART_ERROR:
    case M66_EV_RX_OVERFLOW:
        /* Log error and check wiring, servicing rate, and buffers */
        break;
    default:
        break;
    }
}

After successful M66_Init(), register it:

M66_RegisterCallback(&hm66, M66_OnEvent, NULL);

The callback must be short. Avoid long printf, delays, network operations, or blocking AT commands inside it. If needed, only set a flag/message to your task queue.
8. Short API Examples
8.1 AT Test and Signal Quality Check

int rssi = 0;
int ber = 0;
M66_Status st;

st = M66_Test(&hm66);
if (st == M66_OK)
{
    st = M66_GetSignalQuality(&hm66, &rssi, &ber);
}

Only consider rssi and ber valid when the function returns M66_OK. Check the AT manual for RSSI/BER values and the meaning of invalid readings.
8.2 Sending SMS

M66_Status st = M66_SMSInit(&hm66, 1U); /* text mode */
if (st == M66_OK)
{
    st = M66_SMSSend(&hm66, "+989121234567", "M66 test", 60000U);
}

The number is an example; replace it with a real number. Character limits and UCS2/Persian support depend on the implementation and firmware.
8.3 USSD

M66_Status st = M66_USSD(&hm66, "*100#", 30000U);

The USSD code is an example. The response may be encoded text or UCS2 and depends on the operator. Replace the string for other USSD codes.
8.4 Enabling GPRS

M66_Status st = M66_GPRSInit(&hm66,
    "your.apn",
    "",
    "",
    60000U);

Replace your.apn with the SIM card operator's APN. Some SIM cards require username/password. GSM network registration alone does not mean GPRS is active.
8.5 TCP: Connect and Send

static const uint8_t payload[] = "GET / HTTP/1.0\r\nHost: example.com\r\n\r\n";

M66_Status st = M66_SocketOpen(&hm66,
    0U,
    "TCP",
    "example.com",
    80U,
    60000U);
if (st == M66_OK)
{
    st = M66_SocketSend(&hm66, 0U, payload,
        (uint16_t)(sizeof(payload) - 1U), 30000U);
}

This example only shows sending. For receiving, use M66_SocketReadData() and check the result. Test servers may not accept HTTP/1.0. In production, also verify TLS, DNS, and connection loss handling.
8.6 HTTP GET

int http_status = 0;
int32_t content_length = -1;
uint8_t body[512];
size_t received = 0U;

M66_Status st = M66_HTTPGet(&hm66, 60000U,
    &http_status, &content_length);
if (st == M66_OK)
{
    st = M66_HTTPRead(&hm66, body, sizeof(body), &received, 30000U);
}

M66_HTTPGet() must succeed before M66_HTTPRead(). HTTP responses may be larger than the buffer. For large responses, read in multiple chunks using received. HTTPS works only if supported by the firmware and server TLS settings.
8.7 MQTT

M66_Status st = M66_MQTTOpen(&hm66, 0U, "broker.example.com", 1883U, 30000U);
if (st == M66_OK)
{
    st = M66_MQTTConnect(&hm66, 0U, "stm32-m66-client", "", "", 30000U);
}
if (st == M66_OK)
{
    st = M66_MQTTPublish(&hm66, 0U, 1U, 0U, 0U,
        "device/test",
        (const uint8_t *)"hello",
        5U,
        30000U);
}

This API is only usable on firmwares that support the expected MQTT commands. If the modem returns ERROR, match the command name and syntax with the AT manual of that firmware.
9. Recommended Testing Sequence

    Start with a proper modem, SIM card, power supply, and antenna.
    Bring up only UART and run M66_Test().
    Check manufacturer, model, firmware, SIM status, and RSSI.
    Check network registration status and wait for successful registration.
    Test SMS.
    Test GPRS/APN and IP acquisition.
    Test TCP with a simple server, then verify data reception.
    Test HTTP GET, then POST and response reading.
    Test USSD, calls, and DTMF separately.
    Test FTP, MQTT, and HTTPS only after confirming firmware support.
    Perform long-term testing and log M66_GetStats(), UART errors, RX overflows, and missed events.

10. Common Errors

| Symptom                        | Checks to Perform                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------- |
| `M66_Test()` times out         | TX/RX swapped, wrong baud, missing common GND, modem off, PWRKEY, voltage level   |
| Intermittent incomplete replies| Late `M66_Process()` calls, small buffers, long delays in loop, callback conflicts|
| UART error                     | DMA/IRQ, GPIO alternate function config, baud rate, modem power                   |
| SIM not ready                  | SIM orientation, PIN, power, antenna, network status                              |
| Network not registered         | Antenna, network coverage, SIM card, supported bands, operator 2G service status  |
| GPRS not activating            | APN, network registration, data plan credit, firmware-expected command syntax     |
| TCP connection fails           | DNS, address/port, server firewall, internet access, operator restrictions        |
| HTTP/HTTPS errors              | URL, HTTP method, body length, certificate/TLS, system time, firmware capabilities|
| MQTT/FTP not supported         | Check firmware version and AT manual; not all features are guaranteed in every build |

11. Security and Product Quality Notes

    Do not log APN credentials, MQTT/FTP passwords, or confidential data in production.
    Validate inputs such as URL, hostname, topic, phone number, and payload.
    Do not trust server responses; validate length, status code, and content.
    For networking, define timeouts, limited retries, backoff, and reconnect handling.
    Do not assume TLS/HTTPS is secure just by enabling an option. Certificates and required TLS versions must match the modem firmware capabilities.
    If a command is missing from the AT manual or the modem returns ERROR, consider that feature unsupported for that firmware version until proven otherwise on hardware.

12. Delivery Checklist

     Project builds with the exact STM32F4 model and selected HAL version.
     UART and DMA initialize without errors.
    M66_Process() runs at short, predictable intervals.
     AT, SIM, RSSI, and registration have been verified.
     SMS send/receive tested.
     GPRS, DNS, TCP, and actual payload reception tested.
     HTTP GET/POST and body reading tested.
     USSD tested with real operator.
     No duplicate HAL callbacks.
     Long-term testing and network disconnection recovery performed.
     FTP/MQTT/HTTPS verified only if supported by the firmware.
